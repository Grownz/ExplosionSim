# Working agreement

## Cross-platform rule

Explosion Simulator ships for **Windows x64 (Direct3D 11)** and **Linux x64
(SDL3 + Vulkan)**. Every change must be implemented and tested on both
platforms in the same change set.

This applies to:

- shared code in `src/core`, `src/sim`, `src/scene`, `src/gfx/rhi`,
  `src/gfx/RhiEulerSolver.*`, `src/gfx/GpuVolumeBaker.*`,
  `src/gfx/GpuParticleSystem.*`, `src/platform`, `src/app/SettingsPath.*`;
- renderer changes: the D3D11 and Vulkan backends must expose the same
  behaviour, and the reduced-order chain and the high-fidelity solver must
  render the same result within the documented capture tolerance;
- shader changes: HLSL sources must be recompiled for both DXC (DXIL) and
  SPIR-V, and the SPIR-V outputs checked into or generated by the Linux build
  must be regenerated;
- UI changes: the Windows ImGui panel and the Linux ImGui panel
  (`src/app/LinuxUi.*`) must stay feature-equivalent;
- packaging, settings, docs and changelog entries.

## Required verification

Windows (from the repository root):

```powershell
cmake --preset windows-x64
cmake --build --preset release
ctest --preset release
```

Linux (native or WSL):

```sh
cmake --preset linux-x64
cmake --build --preset linux-release
ctest --preset linux-release
```

For rendering changes, also run the headless capture parity check on Linux and
compare it against the checked-in Windows reference:

```sh
./build-linux/explosion_linux --settings tools/capture_settings.ini \
  --headless --width 320 --height 180 --frames 1 --time 0.1 --charge 0.2 \
  --distance-scale 0.55 --screenshot /tmp/ro.png
python3 tools/compare_png.py tools/reference/win_capture.png /tmp/ro.png \
  --tolerance 20 --max-fraction 0.20
```

Run the same for `--high-fidelity --solver-resolution 32
--no-solver-auto-scale --time 0.01` against
`tools/reference/win_hf_capture.png` (`--tolerance 22 --max-fraction 0.30`).

Changes to the simulation core or physics also need the sanitizer suite:

```sh
cmake -S . -B build-asan -G Ninja -DCMAKE_BUILD_TYPE=Debug \
  -DEXPLOSION_SANITIZE=ON -DEXPLOSION_BUILD_VULKAN_SMOKE=OFF
cmake --build build-asan --parallel
ctest --test-dir build-asan --output-on-failure
```

CI runs all of the above on every push; a change is not done until the
`windows`, `linux-core`, `linux-sanitizers` and `capture-parity` jobs are
green.

## Platform-specific code

- Keep `src/sim`, `src/scene` and `src/core` free of Win32, D3D11, Vulkan and
  SDL types. Add the seam to `src/gfx/rhi/Rhi.h` or
  `src/platform/Platform.h` instead of an `#ifdef`.
- `#ifdef` is only acceptable for a genuinely platform-specific feature. Such a
  feature must be documented in `docs/linux-port.md` and in the changelog, and
  must not silently degrade the other platform.
- When a feature is intentionally platform-only (see below), the shared code
  must still build and behave correctly on the other platform.

## Known intentional asymmetries

| Area | Windows | Linux | Handling |
|---|---|---|---|
| Graphics API | D3D11 | Vulkan | Same RHI surface; parity via capture comparison |
| Self-updater | in-app updater | none (replace the archive) | Documented in the changelog and `docs/linux-usage.md` |
| UI | ImGui (Win32/D3D11) | ImGui (SDL3/Vulkan, F1) | Keep the panels feature-equivalent |
| Packaging | zip | tar.gz + `install.sh` | Both attached to each release |
| Performance | D3D11 numbers | Vulkan numbers | Same-GPU-class comparison still pending |

## Reporting blockers

If a change cannot be completed or verified on both platforms, state:

1. which platform is affected and which step fails (configure, build, test,
   capture, package);
2. the concrete error or missing capability;
3. the proposed options (for example: add the missing backend seam, guard the
   feature behind the RHI, defer the feature with a documented limitation, or
   fix the test/tooling first) with a recommendation.

Do not silently ship a one-platform change.
